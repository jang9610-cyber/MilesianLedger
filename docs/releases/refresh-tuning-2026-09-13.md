# 공통 시세 수집 주기 조정 — 2026-09-13

전체 매물 시작 간격을 180분에서 120분으로 줄인다. 판매 완료 내역은 20분 간격을 유지한다. 앱의 갱신은 기존처럼 공통 완료본을 다운로드하며 개별 검색으로 넥슨 API를 요청하지 않는다.

## 예산과 저장 최적화

- 내부 SQL 보호 예산: 하루 쓰기 60,000행·읽기 3,000,000행 유지.
- 넥슨 호출: 서버 자체 설정 10,000회 중 자동 수집 8,000회까지 유지.
- 중간 페이지 체크포인트에서 인덱스가 있는 `state`를 다시 지정하지 않는다. 마지막 페이지에서만 완료 상태와 완료 시각을 변경하며 트랜잭션·재시작·중복 방지 처리를 유지한다.
- 네이티브 workerd 측정: 중간 체크포인트 쓰기 2행→1행, 완료 체크포인트 2행. 마지막 예산 저장은 1행이므로 정산 가산량을 기존 4행에서 2행(실제 1행+여유 1행)으로 조정한다. 가산량 보정 자체는 DB 쓰기 절감이 아니다.
- 예산 부족 시 추가 수집을 중단하고 이전 완료본을 제공한다. 내부 예산은 계정 전체의 다른 Worker 사용량까지 통제하지 않는다.

## 대표규모 24시간 검증

로컬 Miniflare/workerd의 네이티브 SQLite 카운터로 실제 `reserveCollectionPage`, `commitPage`, `settleCollectionPage`, `cleanup`을 실행했다. 거래 72회×26페이지와 전체 매물 12회×318페이지, 총 5,688페이지를 처리했다. 모든 거래 ID가 새로 들어오는 보수적 조건이며 이전 매물과 페이지 삭제를 포함한다.

이는 실제 이용자 부하나 운영 24시간 실측값이 아니다. 페이지마다 묶음 하나가 저장되는 합성 데이터를 사용했으므로 SQL 행 쓰기를 재현하며, 실제 500개 아이템의 바이트 크기·압축 비용까지 재현하지는 않는다. 8일 만료 정리·gzip 게시·Coordinator·Alarm 비용은 위의 별도 여유로 추정했다. 매물 페이지가 늘어나거나 실패 재시도가 생기면 소비량도 늘어난다.

서버 테스트 118개와 Wrangler 번들 검증을 통과했다. 120분 매물·20분 거래 일정, 재시작 후 일정 유지, 실행 중 중복 시작 방지, 60,000행 예산 보호와 체크포인트 원자성을 검사했다.
